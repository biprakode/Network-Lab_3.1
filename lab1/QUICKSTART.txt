RUN IN TWO TERMINALS:
---------------------

  Terminal 1 (Receiver - runs FIRST):
  $ ./receiver output.txt crc32
  # Waits for connection... (ready after ~1 second)

  Terminal 2 (Sender):
  $ ./sender data.txt crc32
  # Connects, sends frames, closes connection

  Terminal 1 (Receiver output):
  seq=0 ACCEPTED len=44
  seq=1 ACCEPTED len=44
  seq=2 ACCEPTED len=44

TROUBLESHOOTING:
----------------
  Q: "Connection refused"
  A: Start receiver first in Terminal 1, wait 1 second before starting sender

  Q: "All frames rejected"
  A: Make sure both sender and receiver use SAME scheme (e.g., both crc32)

  Q: "Files don't match"
  A: Should never happen if all frames are ACCEPTED - check diff output

  Q: "Port already in use"
  A: Wait a few seconds for port to be released, or: killall receiver

KEY POINTS:
-----------
  ✓ Always start receiver first
  ✓ Both programs must use the same scheme
  ✓ Each frame is 64 bytes (16B header + 44B payload + 4B trailer)
  ✓ Last frame may have partial payload
  ✓ FCS = Frame Check Sequence (error detection code)
  ✓ All frames must be ACCEPTED for perfect transfer
